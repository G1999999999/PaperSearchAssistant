# PaperSearchAssistant2：技术与算法说明

本文档概括本项目的**技术选型**与**检索 / 推理相关算法与策略**，便于快速了解实现思路。运行方式与目录结构仍以 [PROJECT_MANUAL.md](PROJECT_MANUAL.md)、[RUN.md](RUN.md) 为准。

---

## 1. 项目定位

PaperSearchAssistant2 是一个**面向论文与本地知识库的 RAG + Agent 服务**：支持 arXiv 检索与 PDF 入库、多 namespace 向量检索、多轮对话、可选联网补充、多模态（文本 + 图片）问答，并在论文场景下叠加结构化存储（PostgreSQL）、缓存（Redis）与更细粒度的检索管线。

---

## 2. 技术栈概览

| 类别 | 技术 / 库 | 用途 |
|------|-----------|------|
| Web 与 API | **FastAPI**、Uvicorn、Pydantic、python-multipart | HTTP 服务、请求体验证、文件上传 |
| LLM 编排 | **LangChain**（`langchain-core` / `langchain-openai` / `langchain-community` / `langchain-text-splitters`）、**LangGraph** | 文档抽象、工具调用、可选图编排主流程 |
| 对话与嵌入模型 | **通义千问（OpenAI 兼容 API）** + **HuggingFaceEmbeddings**（本地，如 Qwen3-Embedding） | Chat 生成答案；向量与 Chroma 语义空间一致 |
| 向量数据库 | **Chroma**（`langchain-chroma`） | 按 namespace 分 collection，本地持久化 `data/chroma` |
| 稀疏检索 | **rank_bm25**（BM25Okapi） | 关键词检索，与稠密向量混合 |
| 重排序 | **sentence-transformers**（CrossEncoder） | 查询–文档对打分，两阶段检索精排 |
| 论文与文档 | **arxiv**、**pypdf**、**PyMuPDF**、**python-docx**、**openpyxl**、**beautifulsoup4**、**lxml** | arXiv 元数据/PDF、Office 与网页解析 |
| 结构化存储（增强管线） | **SQLAlchemy**、**PostgreSQL**（**psycopg**）、迁移 SQL | 论文分块、章节、摘要、全文检索（FTS）等 |
| 缓存与队列 | **Redis** | 章节/摘要等缓存、与异步任务配合（见 `tools/storage/redis/`） |
| 联网搜索 | **duckduckgo-search**、自研抓取（如 `web_page_fetch`） | 补充检索与页面正文 |
| 协议扩展 | **MCP**（Model Context Protocol） | 可选 MCP 工具/服务集成（如天气等） |

依赖版本见项目根目录 `requirements.txt`。

## 3. 核心算法与检索策略

### 3.1 稠密向量检索（语义检索）

- 文档经 **TokenTextSplitter** 等切块后，用本地 **Embedding 模型**生成向量，写入 **Chroma**，检索时为查询生成同空间向量，按**相似度距离**（余弦距离等，实现以 Chroma/LangChain 为准）取 Top-K。
- 支持 **MMR（Maximal Marginal Relevance）**：在候选集合上平衡**与查询的相关性**与**结果之间的多样性**（见 `tools/rag/math_utils.py` 与 `config` 中 MMR 相关参数）。

### 3.2 BM25（稀疏检索）

- 使用 **BM25Okapi**（`rank_bm25`）在内存中为 namespace 内文档建索引；分词策略兼顾英文词与中文单字（`tools/rag/bm25.py`）。
- 与向量检索形成**互补**：专有名词、精确匹配往往 BM25 更稳。

### 3.3 多路排序融合：RRF 与加权 RRF

- **RRF（Reciprocal Rank Fusion）**：将多路有序列表按名次倒数融合为单一排序，避免不同打分尺度不可比的问题（`tools/rag/bm25.py` 与 `tools/retrieval/fusion.py`）。
- **加权 RRF**：各路列表可带通道权重；并可对单条文档按 **metadata** 做意图加权（如表格/图片/摘要类 chunk，`metadata_intent_boost`）。

### 3.4 两阶段检索：CrossEncoder 重排（Rerank）

- 第一阶段：向量 + BM25（及可选多 query）得到较宽候选集。
- 第二阶段：用 **CrossEncoder** 对 (query, document_text) 打分，按相关性重排截断 Top-K（`tools/rag/rerank.py`）。
- 论文场景下可将 **标题、章节、chunk 角色**等与正文拼成结构化证据文本再送入 CrossEncoder，提升可解释性与稳定性。

### 3.5 多查询与结果合并

- **查询扩展**（`tools/rag/language.py`）：可生成检索用变体 query，扩大召回。
- **子问题拆分**（可配置）：复合问题拆成多个子查询分别检索，再用 **`merge_ranked_lists`** 按分数去重合并（`tools/rag/math_utils.py`）。
- **公共 namespace 合并**：会话私有分区与公共知识库分区并行检索后融合（`tools/rag/retrieval_merge.py`），避免会话内检索丢失公共论文库内容。

### 3.6 路由与意图（非单一算法，而是规则 + 结构化决策）

- **`build_query_route`**（`tools/retrieval/query_router.py`）：在规则路由基础上输出意图（如论文检索/阅读/问答）、是否偏好本地、是否需要表格/图、是否触发联网等；高置信本地论文命中时可强制 **local_first** 并抑制联网。
- **LangGraph 编排**（`tools/agent/langgraph_orchestrator.py`，受 `RAG_USE_LANGGRAPH` 控制）：将「路由 → 本地检索 → 工具/天气/历史 → RAG 生成」等拆成节点，便于追踪与扩展。
- **经典 `RAGAgent`**（`agent.py`）：保留 Middleware 钩子（before/after agent & model）、工具循环（arXiv、知识库、天气等）与 RAG 主链路。

### 3.7 检索充分性评判（LLM-as-Judge）

- **`retrieval_judge`**（`tools/rag/retrieval_judge.py`）：由 LLM 对「当前检索片段是否足以回答问题」打分并给出是否需联网及建议 **web_queries**，用于**自适应联网补充**，而非固定触发搜索。

### 3.8 论文专用管线（结构化存储 + 多通道检索）

在启用 PostgreSQL/Redis 等组件时，论文检索会组合多条通道，例如：

- **Chroma 向量 + BM25**（论文 namespace 内可调 Top-K profile：fast/balanced/deep）。
- **PostgreSQL 全文检索（FTS）** 作为一路稀疏/全文通道（`fts_search_chunks`）。
- **查询理解**：`analyze_paper_query`、`subquestions_for_decomposition`（`tools/retrieval/query_understanding.py`）等，支持分解与扩展。
- **上下文扩展与打包**：`expand_and_pack_context`（`tools/retrieval/context_expander.py`）、**缺失证据检测**（`missing_evidence_detector.py`）、**章节回退查询**（`section_fallback.py`）。
- **多通道内容问答**：`paper_content_qa.py`、`figure_retriever` / `table_retriever` 等面向图、表证据的子检索。
- **Redis**：章节角色、摘要 bundle 等缓存，降低重复计算与数据库压力。

### 3.9 本地论文库与匹配

- 本地 PDF/元数据索引（如 `tools/storage/paper_library.py`、`local_paper_matcher.py`、`local_paper_service.py`）与 **会话论文状态**（`session_paper_state.py`）配合，实现「优先本地、再 arXiv/联网」的产品策略（细则见同目录下 `LOCAL_PAPER_PRIORITY_RULES_CN.md` 等文档）。

### 3.10 其他机制（简要）

- **时间相关查询扩展**（`temporal_context`）：对「最新/今年」等表达做时间锚点与搜索 query 增强。
- **人工审批（Human-in-the-loop）**：敏感操作（如删除文件）走 `approvals` 流程。
- **长记忆**（`long_memory`）：可选记忆写入与检索，用于跨轮次偏好或摘要。

## 4. 默认检索策略命名（与代码对齐）

配置项 `DEFAULT_RETRIEVAL_STRATEGY`（见 `config.py`）默认多为 **`hybrid_rerank`**，语义上对应：**稠密检索 + BM25 混合（RRF 类融合）+ 可选 CrossEncoder 重排**。具体分支以 `NamespaceVectorStore` 内策略实现为准（`tools/rag/knowledge.py`）。

## 6. 相较 `PaperSearchAssistant`（一代）主要解决什么问题

以下对比上一代 `PaperSearchAssistant`。二代在**不丢弃**一代「Chroma + 混合检索 + RAGAgent + 工具」主线的前提下，针对论文场景与工程落地补了短板。

| 痛点（一代典型表现） | 二代做法与收益 |
|----------------------|----------------|
| **对话与嵌入强绑定远程 API** | 一代嵌入走 **OpenAIEmbeddings（与 Chat 同一兼容接口）**，离线或内网只跑本地 Chat 时，向量空间与线上不一致或无法嵌入。二代用 **`runtime_settings` + `RAG_NETWORK_MODE`** 区分在线/离线对话，**嵌入固定本地 HuggingFace**（如 Qwen3-Embedding），Chroma 语义空间不随「是否联网」漂移。 |
| **Chat 主流程集中在单文件分支，难观测、难扩展** | 二代可选 **`LangGraph`**（`RAG_USE_LANGGRAPH`）把路由、本地检索、图片相关性、论文 fallback、检索评判、联网合并、最终生成拆成**显式节点**，配合 `trace_event` 更易调试与迭代。 |
| **论文检索≈通用向量库检索，缺结构化证据与 SQL 通道** | 二代增加 **PostgreSQL**（分块、章节、摘要等）与 **Redis** 缓存，在 `paper_retriever` 中组合 **Chroma + BM25 + FTS + 重排 + 查询理解/子问题/上下文扩展/缺失证据/章节回退/图表子检索** 等多阶段策略；一代无该层 `tools/retrieval/*` 与 SQL 依赖。 |
| **路由粒度偏粗，本地论文优先级难系统化** | 二代 **`build_query_route`** 输出意图、来源偏好、表格/图需求、置信度等，并与本地论文匹配阈值联动（高置信可 **local_first**、抑制无谓联网）；规则仍在一代 `router` 上扩展，但决策结构化、可配置。 |
| **无多模态问答链路** | 一代 `agent` / `main` 侧无用户图上传与多模态消息组装。二代支持 **聊天图片上传**、**多模态 user content**、以及「是否把用户图纳入 RAG 上下文」的**相关性判断**，适配读图/对照类问题。 |
| **环境配置方式单一** | 二代支持 **`.env.runtime` → `.env`** 加载顺序（`runtime_settings.py`），便于区分机器相关路径与密钥；一代主要在 `main.py` 单次 `load_dotenv()`。 |

**简要结论**：一代适合讲清「RAG + hybrid + rerank + 工具」闭环；二代在**部署模式（在线/离线）与向量一致性**、**论文深度检索与结构化存储**、**流程编排与可观测性**、**多模态**上做了实质性升级，而不是简单复制目录。
